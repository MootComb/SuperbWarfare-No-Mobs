# 枪械 HUD 实施设计 v1.1

日期：2026-10-18。状态：整体方案已认可；v1.1 按用户最后补充加入虚拟备弹，并修正所有文字与图标锚点。此版本的对齐约束覆盖 v1.0 中关于资源框中心固定的旧描述。

## 1. 范围与固定约束

保留基础 HUD 的信息结构、风格与字体：枪械英文名、弹药英文名、枪械图标、开火模式键位与图标、当前弹量和备弹。按第 4 节的锚点纠正位置与对齐。不要把 HUD 改成卡片、深色底板、菜单或常驻弹种列表。

新增或优化的内容只有：四角资源承载区域、组合资源符号、开火模式/弹种序号、图标切换与换弹动画、右上角虚拟备弹，以及明确的对齐锚点。

原型中的 600×270 画布、手绘像素文字和示意数值便于观看，不是替换游戏真实坐标、Minecraft 字体或 GunData 数值的依据。实施时继续读取屏幕尺寸、GUI 缩放和 WEAPON_HUD_X/Y_OFFSET，并沿用现有基础区渲染。

## 2. 信息语义

| 情况 | 主弹量区 | 资源座 |
| --- | --- | --- |
| 普通弹药，有弹匣 | 大字为弹匣发数；小字为备弹 | 单一普通玩家弹药默认不增加资源框 |
| 普通弹药，背包供弹 | 只显示一行大字备弹 | 多弹种或特殊来源时显示 |
| 能量，背包供弹 | 只显示一行大字能量百分比 | 闪电图标，不重复百分比 |
| 能量，有弹匣 | 大字为弹匣发数；小字为枪械电量百分比 | 闪电图标，不重复百分比 |
| 多种可切换弹药 | 沿用所选弹种对应的弹量规则 | 当前弹种图标/来源组合，以及框下序号 |
| 生命/饥饿/经验等 | 沿用实际消耗策略提供的可用弹药语义 | 使用相应资源符号；不在资源座旁再显示原始数量 |

资源座回答“消耗什么”，弹量区回答“还剩多少”。资源框内、旁边均不再增加 ×数量、百分比、生命点数或经验点数。虚拟备弹作为独立附加信息显示在当前弹量的右上角。

### 虚拟备弹：超级星星炮

`super_star_shooter.json` 配置为 300 发弹匣，`AmmoType` 为 `100 minecraft:nether_star`，一颗下界之星提供 100 发。

- 换弹前示例：弹匣 299 发，33 颗完整下界之星对应 3300 发备弹，虚拟备弹为 0。
- 换弹消费一颗下界之星，其中 1 发补入弹匣，余下 99 发进入虚拟备弹。
- 换弹后示例：大字 `300`、下方备弹 `3200`，当前弹量右上角青色小字 `+99`。
- 99 发不计入当前弹匣，不能显示成 399，也不重复计入下方的 3200。备弹的实际组成是 3200＋99；示例总弹量守恒为 3599 发。
- 虚拟备弹大于 0 才显示；为 0 时隐藏。读取真实 virtualAmmo，不按弹药物品数量推算固定 99。
- 位置随当前弹量文本实际宽度计算：附加文本左边缘位于主数字右边缘之后，并向上抬起。参考原型中间隔 8 画布像素、上移 14 像素；使用 `#55FFFF`，字号小于主数字。
- 主数字位数或内容变化时重新测量宽度，不能用固定位置挤压或覆盖主数字。虚拟备弹不放进资源框。
- 原型的开始换弹按钮会重设到示意换弹前状态；生产环境只显示实际 GunData，不得人为重置弹量。

生命、饥饿、经验策略目前也可能被归类为 ITEM；图标不能只依赖宽泛的消费类型枚举，必须依据具体来源/策略。经验策略使用总经验点数，不是经验等级。

## 3. 四角资源座

- 无底色、无完整边框，只保留白色四角和与原 HUD 一致的暗色像素阴影。
- 单来源参考尺寸为 20×20 逻辑像素，物品贴图约 16×16；每角约 3×3、线宽约 1。数值是比例参考，应适配现有 GUI 缩放。
- 物品使用实际 ItemStack 贴图；能量为白色闪电，生命为白色心形，饥饿为白色鸡腿，经验为白色 XP 像素符号。新来源应能注册自己的图标。
- 资源框左边缘与右侧弹量文本列左边缘固定对齐。来源增加时只向右加宽；图标组和框下的弹种序号均居中于当前框。
- 资源框相对 v1.0 稍微下移；原型由顶部 173 调整到 181 画布像素。框下仍留出清晰的序号间距。
- 普通单一玩家弹药不必额外显示资源座，避免改变基础 HUD 的简洁程度。能量、物品型特殊来源、多弹种和组合来源使用资源座。

## 4. 两套序号

开火模式继续使用原图标和 COD 风格短横线：AUTO/BURST/SEMI 的横杠、TOP/DIR、RPM 数字都保留。

- 开火模式的“当前/总数”位于短横线正下方，居中对齐该模式承载区。
- 弹种/资源组合的“当前/总数”位于四角框正下方，居中对齐当前框宽度的中心；组合框变宽时不能保留旧的全局中心。
- 两套序号使用相同基线、小号像素字；当前序号白色，斜杠和总数灰色。
- 各自总数大于 1 时显示，等于 1 时隐藏 1/1。这里统一了多模式序号的显示规则，不能继续只在模式数大于 3 时显示。
- 序号都在图标下方，不放进框内，不把两个 A/B 挤在图标右侧。
- 为 TOP/DIR 和 600/1200 等较宽图标预留固定模式区域，避免模式变化导致键位、横线或序号跳动；正常/大尺寸图标仍按原资源尺寸规则处理。

### 全局文字和图标对齐

用武器图标承载矩形的中轴 `W` 和右侧弹量列左边界 `A` 建立锚点，不依赖不同 PNG 中不透明像素的形心：

1. 武器名称、弹药名称的文本矩形中心，以及武器图标承载矩形中心，全部对齐 `W`。
2. 当前弹量、备弹都左对齐 `A`。资源框左边缘也对齐 `A`，框的宽度变化不得改变左边缘。
3. `[N]` 是右对齐文本，其右边界位于 `W − g`；固定宽度开火模式承载区的左边界位于 `W ＋ g`，二者离中轴等距，使用较小间距。键位文本变长时向左增长。
4. 开火模式图标在自身承载区居中，短横线与开火模式 A/B 也对齐该承载区中心。弹种 A/B 对齐资源框中心，两种 A/B 都是居中文本。
5. 不把开火模式图标/序号对齐整个 HUD，也不把资源框按旧的固定中心双向扩展。

600×270 参考画布的具体对应为：`W=190`；枪图左侧 94、宽 192；名称中心 190；`A=343`；`g=6`，所以 `[N]` 右边界为 184、模式承载区左侧为 196、宽 48、中心 220。资源框左侧为 343、顶部为 181，单资源框宽 40、组合框宽 104；各自 A/B 中心为 363、395。绝对数值仅是预览尺度，实施时保留以上关系并适配现有 GUI 坐标。

## 5. 可切换弹种与同时消耗来源

一个可切换的 AmmoType/AmmoConsumer 可以有多条 Ammo 来源。数组中的来源表示同时消耗，不能被当成多个可切换弹种。

Taser 的当前配置示例：

```json
"AmmoType": {
  "Ammo": [
    "superbwarfare:taser_electrode",
    "400 fe"
  ]
}
```

这是一种弹药组合，由电极和每发附加 400 FE 两个来源构成。

- 一个加宽四角框整体包住“电极图标 ＋ 闪电”。小号加号只连接同一组的同时消耗来源。
- 只有这一组时，不显示 1/2。
- 有五种可切换组合时，框下显示例如 2/5；组内有几个图标不影响分母。
- 主弹量与备弹继续按现有主来源/弹匣语义显示。Taser 的示意 1/24 指弹匣电极与备用电极，不表示还有 24 次完整的能量供给。
- 400 FE 是每发的消耗成本，不是备弹量，不显示成另一个弹种编号。
- 副来源不足时，仅对应图标使用低资源颜色，并加小号 !，以同时提供形状提示；不要因主来源尚有数量而错误表达所有来源都可用。

## 6. 弹种队列切换

在实际所选弹种/组合已经发生变化时触发，不能仅按按键猜测切换是否成功。

| 动作 | 进入图标/组合 | 退出图标/组合 |
| --- | --- | --- |
| 下一个 | 从右侧框外、约 28% 不透明度开始，向左进入，最终 100% 不透明 | 从框中向左退出，淡至 0 |
| 上一个 | 上述效果镜像 | 上述效果镜像 |

- 标准时长 240ms，平顺减速，无回弹、旋转和额外放大。
- 名称、弹量与序号即时反映已生效的数据，不能等待动画结束才更新。
- 框左边缘固定对齐弹量列；单来源与组合来源之间切换时，框宽可用约 160ms 向右过渡适配内容，组中心和框下序号同步移动以始终居中。不能让左边缘漂移。
- 多来源必须作为整个组合一起移动，不能让电极先进入、闪电后进入，从而短暂表达错误组合。
- 正常状态只显示当前组合；邻近组合只在切换时出现，不常驻显示半透明邻居。
- 为图标横向滑出预留局部可视范围，裁剪边界不得覆盖左侧开火模式。
- 快速连续切换直接追随最新目标，不积压逐项播放；动画结束只保留当前组合，避免残影节点累积。
- 切换开火模式采用约 120ms 的短淡入；保留横线，避免两个模块同时做大幅队列运动。

## 7. 沿用现有 AUI 的武器图标动画

参数来源：`src/main/resources/assets/apricityui/apricity/superbwarfare/ammo_bar.html`，以及 `AmmoBarOverlay.kt` 的 `updateAUIData`、`triggerScale`。

### 切换武器与换弹完成

只对枪械图标执行缩放淡入，名称、弹量、模式图标和资源座不跟随缩放。

| 时间进度 | 缩放 | 不透明度 |
| --- | --- | --- |
| 0% | 1.08 | 0 |
| 30% | 1.15 | 1 |
| 100% | 1.00 | 1 |

- 总时长 500ms，沿用 CSS 默认 ease 的分段节奏，中心为变换原点。
- 真实枪械图标资源变化时播放；不要在每次弹量更新或每帧 DOM 更新时重播。
- 换弹结束后也播放同样的恢复动画。
- 当前 Kotlin 通过临时切换 reloading 类与短暂帧计数重启动画。设计要求保留最终视觉，不要求照搬这个重启技巧。

### 换弹中

- 枪械图标不透明度在 1 与 0 之间往返。
- 每个方向 300ms，alternate；一次完整明暗往返约 600ms，沿用 ease。
- 由真实 reloading 状态控制持续时间；原型的“开始/完成换弹”按钮仅供演示，没有固定的真实换弹时长。
- 结束时先取消闪烁、恢复图标状态，再播放 500ms 的缩放淡入。

### 状态优先级与清理

1. 切换武器：终止上一把枪的换弹闪烁与未完成的图标动画，更新目标图标，再播放切枪动画。
2. 换弹开始：终止尚未完成的缩放动画，进入闪烁。
3. 换弹持续：弹量、弹种或模式更新不能反复重启闪烁。
4. 换弹完成：取消闪烁，再播放恢复缩放。
5. 原型中背包直供场景禁用“开始换弹”；生产环境始终以 GunData.reloading 等实际状态为准。
6. 隐藏/移除 HUD 时清理活动动画与事件，不留旧武器状态。

减少动态效果偏好开启时，跳过位移与缩放，用静态降低图标亮度表达换弹状态，避免持续闪烁。

## 8. 预览与实施的边界

此 HTML 使用浏览器 Canvas、内嵌 PNG 和 Web Animations 制作交互原型，不是 SVG，也不是可直接替换 AUI 模板的生产页面。

实施时应重新对照所安装 AUI jar 内的文档，尤其是 Overlay 生命周期、HTML/CSS 覆盖范围、纹理/物品元素、transform/opacity 动画。不要假定浏览器 API 在 AUI 中同样可用。视觉参考采用同一组位置关系、图标语义和动画参数即可。

- `src/main/java/com/atsuishio/superbwarfare/data/gun/AmmoConsumer.kt`

`preview.html` 是自包含导出，浏览器离线也能播放。`source.html` 保留可编辑片段。`overview.png` 只展示静态布局，动态效果以交互预览和本说明的参数为准。
